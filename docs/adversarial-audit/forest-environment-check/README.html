Group 02 · 24 November 2026 · Diagnostic separate from the submission analysis

Compare the same forest fit on Andrea’s computer

This small check reproduces the January 2023 original forest and no-GDP forest using the committed 440 training rows, five forecast rows and seed 20565. It records software details, predictions and the sampled training counts for each tree. It does not install packages, change model choices or overwrite any project results.

Run the comparison

  1. Extract the complete ZIP into a separate folder. Keep all six supplied files together.
  2. Use the R installation and package library used for the published results, if still available. If software has since changed, state that when returning the output.
  3. In RStudio, set the working directory to the extracted folder. For example, open Check_forest_environment.R and select Session → Set Working Directory → To Source File Location.
  4. Run the following command:
source("Check_forest_environment.R")

Return the complete newly created diagnostic_output folder. The check needs data.table and ranger already installed. Do not update them before recording the original environment.

How to interpret the comparison

Different sampled-training counts identify a difference in random sampling for this exact fixture. They do not alone identify whether the cause is a package version, compiler or standard library. Matching counts with different predictions point to a later part of fitting. A match on this single month does not certify the complete pipeline.

The Windows reference uses R 4.6.1, ranger 0.18.0 and data.table 1.18.6.1. Two complete fresh modeling runs were identical here. The original published RDS artifacts were written with R 4.6.2; the original ranger version was not recorded in the inspected commits.

Keeping the sample counts is checked against an ordinary fit: it changed no predictions in the local test. All original forest settings are retained: 500 trees, depth 5, split minimum 40, leaf minimum 20, mtry 2, replacement sampling, fraction 1, variance splitting and one thread.
